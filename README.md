# Vision Metrics — Retail Analytics & Person Tracking

Профессиональная система интеллектуального видеонаблюдения для ритейла на базе нейросетей **YOLO** и современных трекеров (BoxMOT, ByteTrack и др.). Система позволяет классифицировать роли (Сотрудник / Клиент), отслеживать время нахождения в зонах и формировать детальные отчеты для бизнес-аналитики.

---

## 📂 Структура проекта

Проект организован по модульному принципу:

- **`main.py`** — Точка входа для графического интерфейса (GUI).
- **`cli.py`** — Точка входа для работы через командную строку (CLI) для пакетной обработки.
- **`config/`** — Система конфигурации (настройки моделей, трекеров, путей).
- **`core/`** — Основная логика:
    - `orchestrator.py` — Управление жизненным циклом обработки кадра.
    - `track_processor.py` — Логика ведения и анализа треков.
    - `reid/` — Модели и галерея для повторной идентификации лиц/объектов.
- **`ui/`** — Компоненты интерфейса на PyQt6 (панели мониторинга, редакторы зон).
- **`stream/`** — Модули для захвата видео (VideoSource, BufferManager).
- **`utils/`** — Вспомогательные утилиты для визуализации и мониторинга ресурсов.
- **`data/`** — Директория для хранения видео и результатов обработки.

## ⚙️ Система конфигурации

Все настройки проекта централизованы в директории `config/`.

### 1. Единый "пульт управления"
Главный файл настроек — **`config/settings.py`**. В нем собраны все ключевые параметры системы:
- Версия модели YOLO.
- Тип трекера по умолчанию.
- Параметры Re-ID.
- Флаги логирования.

### 2. Модульные секции (`config/sections/`)
Для удобства настройки разбиты по категориям:
- `yolo.py` — Параметры детектора (пороги, размер кадра, маски).
- `tracker.py` — Глобальные параметры логики трекинга (фильтрация, Re-ID флаги).
- `system.py` — Системные параметры: выбор устройства (CPU/CUDA/MPS) и интервал обработки кадров.
- `analytics.py` — Настройки бизнес-логики (правила классификации ролей).
- `reid.py` — Параметры системы идентификации.

### 3. Настройки конкретных трекеров (`config/trackers/`)
Низкоуровневые параметры каждого алгоритма находятся в отдельных файлах:
- `bytetrack.py`, `botsort.py`, `boosttrack.py` и др.
Здесь настраиваются специфичные для алгоритмов коэффициенты (например, `track_high_thresh`, `match_thresh`, `proximity_thresh`).

## 🚀 Запуск системы

### 1. Графический интерфейс (GUI)
Используется для интерактивной настройки зон (ROI), мониторинга в реальном времени и визуальной отладки.

```bash
python main.py
```

**Особенности GUI:**
- **ROI Selector**: Настройка зон интереса прямо на видео.
- **Resource Monitor**: Отслеживание нагрузки на CPU/GPU и времени инференса.
- **ReID Panel**: Наблюдение за процессом "сшивания" потерянных треков.

### 2. Командная строка (CLI)
Используется для автоматизации и высокопроизводительной обработки видеофайлов на сервере.

```bash
# Базовый запуск
python cli.py --source data/videos/input.mp4

# Запуск с выбором устройства и трекера
python cli.py --source input.mp4 --device mps --tracker boosttrack --batch-size 4

# Полный список параметров
python cli.py --help
```

**Основные флаги CLI:**
- `--source`: Путь к видеофайлу или RTSP-потоку.
- `--device`: Устройство расчета (`cpu`, `cuda`, `mps`).
- `--tracker`: Тип трекера (`boosttrack`, `bytetrack`, `botsort`, `strongsort`).
- `--batch-size`: Количество кадров для одновременной обработки.
- `--frame-interval`: Пропуск кадров для ускорения (1 — каждый кадр, 3 — каждый третий).
- `--output`: Путь для сохранения итогового JSON-отчета.

## 📊 Результаты работы

Результаты сохраняются в папку `data/` в формате иерархического JSON. Отчет содержит полную историю перемещений каждого объекта, его роль и время нахождения в каждой заданной зоне.
